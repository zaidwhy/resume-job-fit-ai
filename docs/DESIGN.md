# DESIGN.md - Resume Job-Fit AI

This documents the UI language **as it actually exists in the code today**. It is a
description, not a spec: nothing here is a new design decision, and nothing here should be
read as license to redesign. Where the app is inconsistent, that is called out explicitly
rather than smoothed over.

Scope: `app.py` and the three pages under `pages/`. Deploy configuration
(`.streamlit/config.toml`, `secrets_bridge.py`'s Cloud-secrets logic) is out of scope for
edits but is referenced below where it explains a color choice.

## 1. Page structure

Streamlit's native multipage-app convention: one entry script plus a `pages/` directory,
sidebar navigation is auto-generated by Streamlit from filenames.

| File | Role | `page_icon` |
|---|---|---|
| `app.py` | Main analyzer: resume + job description in, fit score + 6 generated sections out (tabs) | target emoji |
| `pages/1_Compare_Jobs.py` | One resume against 2-3 job descriptions, ranked | scales emoji |
| `pages/2_Job_Tracker.py` | Saved applications, status board, Altair charts, CSV export | clipboard emoji |
| `pages/3_Company_Research.py` | Company culture/interview-format lookup | magnifying-glass emoji |

All four call `st.set_page_config(..., layout="wide")` independently (Streamlit requires
this per-script; there is no shared config module). `app.py` also sets a page title;
the pages set their own `"<Page> - Resume Job-Fit AI"` title suffix.

Every page begins the same way: `load_secrets_into_env(...)` from `secrets_bridge`, then a
title (`st.title`) and a one-line `st.caption` sub-description immediately under it. Pages
that render results end with the same "Built in public by Zaid Ali Syed" caption footer
(`app.py`, `1_Compare_Jobs.py`, `2_Job_Tracker.py`; `3_Company_Research.py` does not have
this footer - inconsistency, not fixed here since it's a content/behavior change, not a
token cleanup).

## 2. Typography & layout

No custom CSS, no custom fonts, no `st.markdown("<style>...")` global overrides anywhere in
the repo. Typography is 100% default Streamlit chrome (the `sans serif` theme font declared
in `.streamlit/config.toml`) except for font-size/weight set inline per-element via
`style=` attributes on individual `st.markdown(..., unsafe_allow_html=True)` calls - there
is no shared CSS class, every styled element repeats its own inline `style` string.

Layout primitives used throughout, all native Streamlit, no custom layout components:
- `st.columns([...])` for side-by-side panels (2-up compare panels, chip columns, score
  badges next to headers)
- `st.container(border=True)` as the de-facto "card" - used for interview questions, skill
  gap rows, job-comparison results, and tracker entries
- `st.tabs([...])` in `app.py` to switch between the 6 generated sections
- `st.divider()` between logical sections, used liberally and consistently
- `st.expander(...)` for "Copy X" affordances throughout

## 3. Color palette

Everything below is an inline hex literal inside an f-string passed to
`st.markdown(..., unsafe_allow_html=True)`, or a literal string argument to a helper
function. There is no theme/constants module (before this change - see Section 5).

### 3.1 Score-band colors (the score_color pattern)

Three colors encode "how good is this score", using the same >=75 / >=50 / else thresholds
everywhere they appear:

| Hex | Meaning | Band |
|---|---|---|
| `#16a34a` (green) | good | score >= 75 |
| `#d97706` (amber) | medium | 50 <= score < 75 |
| `#dc2626` (red) | low | score < 50 |

Where it's defined/used:
- `app.py` lines 46-51: `score_color(score)` function - the original definition. Used for
  the big score number in `render_analysis` (line 321) and `render_resume_health`
  (lines 440, 461).
- `pages/1_Compare_Jobs.py` lines 51-56: an **exact duplicate** `score_color(score)`
  function, byte-for-byte identical to `app.py`'s, used for the per-job score badge
  (line 142).
- `pages/2_Job_Tracker.py` line 154: the same three values and thresholds again, but
  inlined as a ternary chain instead of a function: `color = "#16a34a" if score >= 75 else
  "#d97706" if score >= 50 else "#dc2626"`.

This is the inconsistency this pass fixes (Section 5): the same three-way rule was written
three separate times instead of being defined once and imported.

`#16a34a` (the "good" green) is also reused as a static accent - not through
`score_color()` - for the "Rewritten" bullet card's left border and label in
`app.py` lines 366/368 (paired with background `#f0fdf4`).

### 3.2 Chip / badge colors

`app.py`'s `chips(items, bg, fg)` helper (lines 54-63) renders a list of strings as
rounded pill spans. Callers pass a `bg`/`fg` pair per semantic meaning:

| Usage | bg | fg |
|---|---|---|
| Matched keywords (`render_analysis`) | `#dcfce7` | `#166534` |
| Missing keywords (`render_analysis`) | `#fee2e2` | `#991b1b` |
| LinkedIn skills to add (`render_linkedin_profile`) | `#dbeafe` | `#1e40af` |

`render_skills_roadmap` (lines 421-425) uses the same green/red family plus one more, for
importance badges, but does **not** call `chips()` - it builds the pill markup inline with
its own dict lookup instead:

| Importance | bg | fg |
|---|---|---|
| High | `#fee2e2` | `#991b1b` (same red pair as "missing keywords") |
| Medium | `#fef9c3` | `#854d0e` |
| Low | `#f0fdf4` | `#166534` (same green fg as "matched keywords", different bg) |

The salary-range badge (`render_analysis`, line 335) is a third, one-off pill pattern
(background `#fefce8`, text `#854d0e`, border `#fde68a`) - same amber text as "Medium
importance" but not sourced from the same place, and it is the only chip-like element with
a border.

Pages 1-3 do not import or call `chips()`; only `app.py` uses it.

### 3.3 Neutral / muted grays

Two different grays are used for de-emphasized text, without a documented distinction:

- `#888` - the `/100` suffix after every big score number, in all three places a score is
  rendered large (`app.py` render_analysis, `app.py` render_resume_health,
  `pages/1_Compare_Jobs.py`, `pages/2_Job_Tracker.py`). Consistent within this one use case.
- `#6b7280` - everywhere else muted/secondary text is needed: the "Original" bullet label,
  resume-health subtitle, sub-score labels (`app.py` lines 359, 448, 464).
- `#374151` - fallback foreground for an importance badge whose key isn't High/Medium/Low
  (dead code in practice; `gap.importance` is always one of those three).
- `#9ca3af` / `#f3f4f6` - the "Original" bullet card's left border and background
  (paired, gray family, mirrors the green `#16a34a`/`#f0fdf4` "Rewritten" pairing).

`#888` vs `#6b7280` is a genuine, minor inconsistency (two named grays doing the same
"de-emphasize this text" job) but is not touched by this pass - unlike the score-band
colors, these are two different design choices for two different-looking pieces of text
(a large number's unit suffix vs. body captions), not a copy-pasted duplicate of the same
rule, so it doesn't meet the "exact traceable duplication" bar this pass is scoped to.

### 3.4 Chart colors (Job Tracker only)

`pages/2_Job_Tracker.py` hardcodes `#4f46e5` three times (lines 52, 90, 103) as the Altair
line/bar chart color, and `#e5e7eb` once (line 91) for zero-count pipeline bars. `#4f46e5`
is the same value as `primaryColor` in `.streamlit/config.toml`. Altair does not read the
Streamlit theme automatically, so this app-side literal is how the chart accent color
tracks the Streamlit theme's primary color today - it is a real duplication (theme file and
Python both encode `#4f46e5`) but fixing it would mean reading `.streamlit/config.toml` from
Python or otherwise touching deploy-adjacent config, which is out of scope for this pass. If
`primaryColor` in `.streamlit/config.toml` ever changes, these three literals would need a
manual matching update.

## 4. Score-color usage isn't only cosmetic

`score_color()` (and its two duplicates) is called only for rendering (text color of a
number/badge). It never affects control flow or persisted data - safe territory for the
consolidation below.

## 5. Change made in this pass

Per PROJECT-GENESIS.md Tier 6 item 42's "de-duplicate a repeated hex color literal into a
named constant" example: the three-way score-band rule from Section 3.1 (`#16a34a` /
`#d97706` / `#dc2626` at thresholds 75/50) was defined three times across three files with
identical values. It is now defined once, in `ui_colors.py`, and imported everywhere it was
previously redefined:

- `app.py`'s `score_color()` function definition removed; imports `score_color` from
  `ui_colors` instead.
- `pages/1_Compare_Jobs.py`'s duplicate `score_color()` function removed; imports from
  `ui_colors` instead.
- `pages/2_Job_Tracker.py`'s inline ternary replaced with a call to the same
  `ui_colors.score_color()`.

The three hex values and the >=75/>=50 thresholds are unchanged - this is a source-location
change only, verified by exact string match, with no visual difference. Nothing else in
Section 3 (chip colors, grays, chart colors) was touched.

## 6. Non-goals

This document does not propose new colors, new components, new layout, or a design-token
system beyond what Section 5 needed. Any further consolidation (the `#888`/`#6b7280` gray
split, the ad hoc importance-badge markup that could call `chips()`, the salary badge's
one-off border) is left for a future, separately-scoped pass - not bundled in here.
